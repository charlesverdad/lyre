# LEARNINGS

Operational gotchas for future agents. Newest first, concise.

## v0.2.0 task D1 — robust paste (2026-07-28)

- **`share_target.action` in the web manifest must be relative** (e.g. `"share"`, not `"/share"`): it resolves against the _manifest's own URL_, not the origin root or the page that linked it — same mechanism as this manifest's existing `start_url`/`scope`/icon paths (all relative). An absolute `/share` breaks under `BASE_PATH=/lyre` (resolves to the wrong origin-root path); confirmed by inspecting the `BASE_PATH=/lyre` build's `build/manifest.webmanifest` and `build/share.html` output directly rather than trusting memory of the spec.
- **`svelte-check` warns (doesn't error) on reading a `$props()`-destructured value at the top level of a component's `<script>`** ("captures only the initial value… reference it inside a closure instead") — e.g. calling a callback prop once during setup, or passing it straight into a constructor. Doesn't fail `just verify` (warnings don't count as errors there), but wrapping the read in a closure (arrow function, or `$effect`) silences it and is the idiomatic fix.
- **Grab-outcome state (URL field, error copy, guided-paste sheet) factors cleanly into a plain class in a `.svelte.ts` file** (`$state` class fields work fine, same rune rules as a component) — this let the add page's main paste textarea trigger the exact same `grabUrl`/`grabFromHtml` flow `GrabInput.svelte`'s own URL field uses (bare-URL paste, share-target hand-off) without duplicating any of that logic. `db/liveQuery.svelte.ts` was the existing precedent for `.svelte.ts` outside `ui/theme.svelte.ts`'s module-singleton style; this task needed a _per-instance_ version instead, hence the class.
- **`sessionStorage`, not a query param, is the right way to hand data from a redirect-away landing route to its destination in a client-only SPA** (`/share` → `/add`): it survives exactly the one navigation needed and doesn't leak the shared URL/text into `/add`'s own address-bar history. Guard every access behind `typeof sessionStorage === 'undefined'` (same pattern as `ui/theme.svelte.ts`'s `localStorage` guards) so it degrades gracefully in privacy modes that block Storage.
- **Chart-region extraction for noisy pastes is pure line-classification + windowing** — no DOM, no site knowledge: score every line (chord line / section label / pattern-header / lyric-adjacent-to-a-chord-line), slide a window that tolerates small internal gaps (stanza breaks), pick the densest window, optionally pull in a header line just above it. Reused the existing `isChordLine`/`matchSectionLabel` heuristics from `plaintext.ts` rather than re-deriving them — single source of truth for "what looks like a chord line" stays in one place.

## v0.1.0 build (2026-07-27, orchestrated multi-agent session)

- **Gate merges on explicit check status, not command chaining.** `gh pr checks N | tail && merge` masks the exit code — PR #10 merged red this way (lint-only failure, hotfixed on the version branch). Use: poll checks, grep for zero `fail`/`pending`, only then merge.
- **`gh pr merge` is blocked by the local permission classifier; `gh api -X PUT repos/<owner>/<repo>/pulls/N/merge` works** and records a proper squash-merge.
- **`svelte/no-navigation-without-resolve` cannot be silenced with inline `<!-- eslint-disable-next-line -->` comments** in this setup — use a scoped `files:` override in `eslint.config.js`. External dynamic hrefs (grab source links) legitimately trip it.
- **Local `just verify` green ≠ CI green** in one case (eslint result diff on fresh install). If a sub-PR's base moved, re-run verify after rebase.
- **`$service-worker`'s `prerendered` paths are already base-prefixed** — mapping `base + p` over them double-prefixes under `BASE_PATH=/lyre`.
- **Tag vs branch name collision**: with branch `v0.1.0` and tag `v0.1.0`, `git push origin v0.1.0` fails ambiguous — push `refs/tags/v0.1.0:refs/tags/v0.1.0`.
- **Kit config lives in `vite.config.ts`** (passed to the `sveltekit()` plugin, supported since kit 2.62) — there is deliberately no `svelte.config.js`; don't add one.
- **Licensing is a hard test-fixture constraint**: no copyrighted lyrics anywhere in the repo, ever — public-domain hymns (Amazing Grace) only. Real grabbed pages stay in session scratchpads.
- **The adversarial review loop caught 5 real correctness bugs pre-merge** (borrowed-chord spelling, "Go"/"Do" parsed as chords, key-relabel transposing, pattern-row leak, `javascript:` href XSS) and E2E authoring caught 2 more (Svelte effect loops). Review every sub-PR; write E2E against the real UI, not the spec.
- **Svelte 5 effect-loop guards**: value-compare before writing state an `$effect` also reads (add page), or `untrack()` the self-referencing read (library liveQuery). Both patterns are in the code with comments.
- **Worktree agents can start on a stale base** — the Agent tool's worktree snapshot is taken from the orchestrator's checkout; agents must `git fetch origin v0.1.0` and branch from `origin/v0.1.0`, and rebase before opening PRs if the base moved (package.json/pnpm-lock conflicts: take origin's lock, re-run `pnpm install`).
